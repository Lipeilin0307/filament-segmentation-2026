# Optional training and exact submission reproduction

`reproduce.ipynb` defaults to **`RUN_TRAINING = False`**. This loads the five supplied model files, checks their SHA256 values, and performs fresh image-to-CSV inference. No training annotations or initialization downloads are needed for that path.

The optional branch calls real training implementations in `sfseg/train.py` and `sfseg/training/`; it is not a placeholder or a call into an unavailable private project. The extracted original definitions, their source hashes, and packaging adaptations are recorded in `verification/training-source-provenance.json`.

## Inspect without training

```text
python -m sfseg.train --plan
python -m sfseg.train --validate-data --data-root PATH_TO_EXTRACTED_OFFICIAL_DATA
python verify_optional_training.py --data-root PATH_TO_EXTRACTED_OFFICIAL_DATA
```

The first command checks the frozen route definitions. The other commands also validate the official training annotation hash and all 707 training image hashes. The verification script checks imports, disabled-by-default execution, all seven actual Base data routes, deterministic crops, and a real grayscale mask/spine crop. It never constructs a model, initializes CUDA, performs backpropagation, or updates an optimizer.

Use the extracted competition dataset containing `train/MAGFiLO_1.0_Annotations_kaggle2026_train.json` and `train/train_images/`. The annotation file has 1,154 independent expert image records covering 707 physical images. These data are obtained through the competition's authorized access process and are not redistributed here. No test annotation file is requested or read.

## Explicitly run a new training job

In the Notebook, set `RUN_TRAINING = True`, then provide `SFSEG_TRAIN_DATA` and `SFSEG_TRAIN_OUTPUT` in the environment. Alternatively:

```text
python -m sfseg.train --execute-training --data-root PATH_TO_EXTRACTED_OFFICIAL_DATA --output-dir NEW_EXTERNAL_TRAINING_DIRECTORY
```

The output must be a new directory outside the release and input dataset. Existing directories are rejected to prevent overwriting the retained submission or historical experiments. At least 150 GiB of free disk is required; this is a startup guard, not a guaranteed peak-space bound. A CUDA GPU and substantial training time are required. Generic initialization assets are downloaded only inside this explicitly enabled path and are verified against `configs/training-initialization.json`.

The runner executes the following fixed recipe:

| Component | Data and budget |
|---|---|
| Base | Seven ConvNeXt-Base U-Nets: `outer-0/1/2`, `single-0/1/2`, and `deployment`. Each uses 72 epochs × 128 updates, batch 4, native 512 crops, retained initialization, augmentation, optimizer/LR schedule and final EMA. |
| Residual refiner | Three excluded-fold refiners plus one full refiner. Each uses 39 epochs × 128 updates with the retained multi-expert loss. |
| HistGBDT | Two regressors using 192 features, 200 boosting iterations each. Targets are mean independent-expert best IoU and fraction of experts with best IoU > 0.5. |
| YOLO11m-seg | The retained A-side 451-image fit split, 57-image selection split, up to 40 epochs with patience 15, 1280 input and batch 4. Only this detector's box proposals are used at inference. |
| Grayscale crop refiner | The same A451/A57 fit/selection roles, ImageNet ResNet34 initialization, 15 epochs, batch 16, 256 crops, mask plus supplied training-spine supervision. The spine output is not used at inference. |

The three Base folds contain 234/233/240 images and are disjoint by physical image, date and image hash. A quality example in fold `h` is generated by `outer-h` Base and refiner `h`; both exclude `h`. A refiner-`h` training image from fold `g` uses a `single-k` Base excluding both `g` and `h`. The full refiner uses outer-fold OOF candidates. The deployment Base uses all 707 images. Expert versions remain separate when sampling training crops and forming refiner/quality targets.

The final five files are written to `NEW_EXTERNAL_TRAINING_DIRECTORY/model-bundle/` with a new SHA256 manifest. The Notebook passes this bundle to the same inference implementation; it does not silently fall back to the retained release weights.

## Calibration and validation limits

The exact submitted pipeline includes **retained source and conditional calibration maps** in `configs/inference.json`. The source map was fitted on the A-side 57-image calibration role, separate from detector fit/selection. Conditional calibration used 190 training-side OOF images. These learned maps are provided as frozen model artifacts, alongside the five weight files. The optional weight-training runner retains these maps and the original thresholds; it does not re-estimate them from a newly trained predictor. `sfseg/training/calibration.py` includes the isotonic fitting calculation for provenance, but the runner does not call it.

A fresh training run is therefore a new set of weights with the retained calibration and postprocessing policy. It is **not claimed to reproduce the historical weights or CSV byte-for-byte**, and would need separate calibration/generalization assessment before competition use. Exact submitted-prediction reproduction is the default supplied-weight path, verified separately by the reference SHA256 and every instance RLE.

For the November 14 release update, the training code was checked without training, as requested by the author. `verification/optional-training-verification.json` records those checks and zero optimizer updates. Full new training execution was not tested. The clean-environment Notebook verification covers the supplied-weight inference branch, not the cost or convergence of a fresh training run.
